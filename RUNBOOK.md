## 2. Core Clinical & Domain Business Logic

### 2.1 Multi-Currency Cost Calculator Engine
The platform includes an interactive cost calculator comparing Western medical costs (US/Europe/UK) against premier accredited hospitals in India and Thailand.

- **Savings Math**:
  $$\text{Savings USD} = \text{Western Cost USD} - \text{Destination Cost USD}$$
  $$\text{Savings Percentage} = \text{round}\left(\frac{\text{Savings USD}}{\text{Western Cost USD}} \times 100\right)$$
- **Currency Conversion**:
  $$\text{Amount MUR} = \text{round}(\text{Amount USD} \times \text{Exchange Rate})$$
  *(Default base rate: $1\text{ USD} = 46.5\text{ MUR}$)*
- **Procedure Pricing Benchmarks**:
  - *Cardiac Surgery (CABG / Valve)*: US $\$120,000$ vs. India $\$6,500$ (95% savings $\approx 302,250\text{ MUR}$).
  - *Orthopedics (Total Knee/Hip Replacement)*: US $\$45,000$ vs. India $\$5,200$ (88% savings $\approx 241,800\text{ MUR}$).
  - *Oncology (Proton Beam / CyberKnife)*: US $\$95,000$ vs. India $\$12,000$ (87% savings $\approx 558,000\text{ MUR}$).
  - *Robotic Urology / Prostatectomy*: US $\$40,000$ vs. India $\$6,000$ (85% savings $\approx 279,000\text{ MUR}$).
  - *IVF / Fertility*: US $\$18,000$ vs. India $\$3,500$ (81% savings $\approx 162,750\text{ MUR}$).

### 2.2 Clinical Inquiry & Triage Lifecycle
Patient inquiries undergo a strict clinical case-management lifecycle:

```mermaid
stateDiagram-v2
    [*] --> new: Patient submits form / WhatsApp sync
    new --> contacted: Coordinator acknowledges within 2 hours
    contacted --> awaiting_documents: DICOM scans / medical records requested
    awaiting_documents --> in_progress: Review by hospital medical board
    in_progress --> quoted: Multi-hospital cost & treatment plan generated
    quoted --> completed: Patient accepts & travel itinerary scheduled
    new --> cancelled: Invalid or duplicate submission
    contacted --> cancelled: Patient withdraws
```

#### Triage Urgency Classifications:
1. **Routine**: Elective orthopedic, cosmetic, fertility, or non-acute surgeries. SLA: 24-hour turnaround.
2. **Urgent**: Active oncology diagnosis, progressive cardiovascular symptoms, organ transplant evaluation. SLA: 4-hour turnaround.
3. **Emergency**: Acute coronary syndrome, critical surgical indications requiring aeromedical evacuation. Immediate 24/7 hotline dispatch.

### 2.3 DICOM / Medical Imaging Protocols
The platform features an embedded in-browser clinical scan viewer for reviewing medical records:
- **Supported Modalities**: CT Thorax, Brain MRI, Knee X-Ray, Abdominal Ultrasound.
- **Diagnostic Windowing Presets**:
  - `Soft Tissue`: Optimized for abdominal and organ parenchyma.
  - `Bone`: High-contrast window for cortical bone and fracture line inspection.
  - `Lung`: Wide window for pulmonary parenchyma and airway tracking.
  - `Invert`: Grayscale inversion for micro-calcification detection.
  - `Thermal`: Pseudo-color mapping for perfusion visualization.
- **Calibrated Caliper Measurement**: Interactive distance calipers scaling millimeters to viewport pixels.
- **PII Anonymization**: All patient identification headers in scans are pseudonymized (e.g. `MED360-ANON-7842`) before presentation.

## 3. Multilingual & Localization (i18n) Engine

The platform supports 3 primary languages with automated fallback:
- **English (`en`)**: International patient default.
- **French (`fr`)**: Regional Francophone default (Mauritius, Réunion, Madagascar, West Africa).
- **Mauritian Creole (`kr`)**: Local vernacular accessibility.

### Localization Rules:
- Dynamic entity attributes use localized field keys (`name_fr`, `name_kr`, `description_fr`, etc.).
- If a localized string is undefined, the engine gracefully falls back to the English (`en`) baseline.
- The language switcher updates the global `i18n.language` and persists user preference across sessions.

## 4. UI/UX Architecture Guidelines (Strict Rules)

### 4.1 Strict Zero-Modal / Zero-Popup Rule (`AGENTS.md`)
- **No Dialog Modals for CRUD**: Creating, editing, or deleting items (hospitals, doctors, specialties, inquiries, case studies, procedures) must **never** open a blocking modal dialog overlay (`<dialog>` or popup).
- **Inline Workstations Only**: All creation and modification workflows use **inline expandable forms**, **in-place editor cards**, or **accordion panels** embedded directly in the page flow.
- **Deletion Confirmations**: Must use inline confirmation banners/bars directly within the active card rather than native `alert()` or modal overlays.

### 4.2 File Size Limit Cap
- Every source code file (`.ts` and `.tsx` in `src/`) must strictly remain $\le 750$ lines of code to maintain modularity and code readability.

## 5. Request Minimization & Performance Caching Architecture

To achieve an **80%–95% reduction in backend requests**, Med360 employs a 5-layer optimization stack:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     5-LAYER REQUEST ELIMINATION ENGINE                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. Inflight Request Collapsing (SingleFlight)                              │
│     - Deduplicates concurrent identical requests into 1 network Promise.    │
│                                                                             │
│  2. L1 RAM Hot Cache                                                        │
│     - In-memory sub-millisecond instant hit (0ms latency).                  │
│                                                                             │
│  3. L2 Persistent Storage Cache                                             │
│     - LocalStorage cache with TTL surviving full browser reloads.           │
│                                                                             │
│  4. Client-Side Derived Projections                                         │
│     - getHospitalById / getFeatured derive locally from cached master lists.│
│                                                                             │
│  5. Mutation-Aware Tag Invalidation                                         │
│     - createHospital automatically invalidates 'hospitals' tag only.        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 9. Incident Response & Disaster Recovery (DR)

| Incident Scenario | Automated Safeguard | Operator Action |
| :--- | :--- | :--- |
| **Supabase Cloud Outage** | `mockEngine` catches database errors and routes operations to local storage fallback. | Check [status.supabase.com](https://status.supabase.com). No code rollback required. |
| **Meta Webhook Failure** | Edge handler returns `200 OK` on errors; client logs fallback to local storage. | Verify `WHATSAPP_VERIFY_TOKEN` in Vercel environment settings. |
| **Core Web Vitals Regression** | Preload links in `index.html` and dimensional constraints on images prevent CLS. | Verify newly added assets are compressed ($\le 150\text{ KB}$) and use explicit `width`/`height`. |
| **Admin Password Compromise** | Session tokens expire automatically on browser close. | Update `VITE_ADMIN_PASSWORD` in Vercel environment variables and redeploy. |
